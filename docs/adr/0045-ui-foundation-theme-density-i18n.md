# ADR-0045: UI foundation: one theme module, density by platform, i18n infrastructure

- Status: Accepted (P03 UX task U1, 2026-11-11; owner decisions U-D4, U-D9–U-D11 in [p03-ux-plan.md](../roadmap/p03-ux-plan.md))
- Date: 2026-11-11
- Deciders: Project owner (direction), implementation
- Related: [ADR-0019](0019-ui-state-management-and-navigation.md), [ADR-0044](0044-navigation-drawer-on-phones.md), [ADR-0018](0018-dependency-license-policy.md) (intl), [ui-ux-architecture.md](../architecture/ui-ux-architecture.md), [architecture-fitness-functions.md](../testing/architecture-fitness-functions.md) (FF-ARCH-10)

## Context
The owner wants a minimal app that shows a lot of content: little chrome, dense rows, neutral colours with accents only where they mean something, and a theme that is easy to change. The screens are about to be redesigned (U3–U5), so strings should not be hard-coded any more, but translating now would be wasted while the UI still changes.

## Decision
**One theme module** (`packages/ui/lib/src/theme/lifeflow_theme.dart`, exported by `ui.dart`). `lifeFlowTheme(brightness, platform:)` is the only place that builds `ThemeData`:
- **Neutral colours (U-D10):** a slate seed `#5B6B78` with the `neutral` dynamic-scheme variant, so surfaces are near grey and the primary is muted (saturation < 0.35).
- **Less chrome:** no surface tint and no elevation on app bars, cards, menus and dialogs. App bars are flat (48 dp with a pointer, 56 dp on phones), do not change colour when content scrolls under them, and have a left-aligned medium title. Cards are outlined.
- **Density by platform (U-D9):** pointer platforms (Windows, macOS, Linux) use compact density, shrink-wrapped tap targets, dense list tiles and slimmer rails and drawers. Phones keep standard density and 48 dp touch targets.
- **Meaning colours:** `LifeFlowColors`, a `ThemeExtension` with light and dark sets (important, overdue, done, cancelled, success, missed, no data, focus, conflict), read with `LifeFlowColors.of(context)`. Each keeps 3:1 against the surface. Meaning is never carried by colour alone.
- **Item palette (U-D4):** `itemPalette`, 12 named colours (Red … Brown), each with a light and a dark tone that keep 3:1 on the surface and on cards (WCAG 1.4.11). Items store an index (U2); `itemColorOf(context, index)` gives the tone. The default display is a left colour bar (U3).
- **Theme setting:** System (default), Light or Dark under Settings → Appearance, stored as a device setting (`SettingsService.themePreference`, registry key `ui.theme`).

**i18n infrastructure (U-D11):**
- `flutter_localizations` and `intl` 0.20.3 (BSD-3-Clause, VS-36) in `packages/ui`.
- `gen_l10n` with `packages/ui/l10n.yaml`: the template is `lib/l10n/app_en.arb`; the generated `AppLocalizations` is in `lib/src/l10n/` (committed, regenerated by `flutter gen-l10n`, also run by `flutter test`/`run` through `generate: true`).
- `context.l10n` (`lib/src/l10n.dart`) gives the strings, and falls back to English where no localizations are installed (isolated widget tests).
- `MaterialApp` installs the delegates; the only supported locale is English. **No translation and no language choice yet.** A language is added by adding `app_<code>.arb`.
- Weekday and month names come from `intl` in the current locale (`schedule_text.dart`).

**Migration:**
- The strings of the screens that stay were moved to the ARB file (about 220 messages, placeholders typed `Object`): profiles, settings, account, data (export/restore), focus, habit, goals, event editor, schedule editor, calendars dialog, schedule fields, shell. The English text is unchanged, so every widget test that finds text still applies.
- The screens being replaced (Tasks, the list calendar, the agenda tile in `task_actions.dart`) are not migrated; their successors (U3–U5) use ARB from the start.
- Plain text helpers (`habit_text.dart`, `messages.dart`, parts of `schedule_text.dart`, the drawer's sign-in status) still return English. They move when their callers pass `AppLocalizations`.
- Command refusals still reach the UI as English sentences; stable codes come with the first translation.
- **Tool:** `tools/l10n/migrate.ps1 <files>` drives `tools/l10n/migrate_strings.dart`:
  - extract the literals into the ARB file, with deduplication;
  - run `flutter analyze`, then repair it: drop a `const` that no longer applies (never a constructor declaration's), and put back a literal with no `context` in scope;
  - prune unused keys.
  - It skips literals split over lines or with quotes inside an interpolation; those are moved by hand.

**FF-ARCH-10** (`tools/fitness/ff_arch_10_ui_strings.dart`, in CI) is a ratchet on raw UI literals (in `Text(…)`, `tooltip:`, `label:`, `title:` and the like) per file, against `tools/fitness/ui_strings_baseline.txt`:
- A file above its baseline, or a new file with any raw string, fails.
- `--update` lowers the baseline and refuses to raise it.
- Baseline at U1: 84 raw strings in 9 files: the three replaced screens 75, the app title 1, and 8 small ones left in data and account messages.

## Consequences
- Every new screen takes colours from the theme and strings from the ARB file. FF-ARCH-10 stops new raw strings.
- Changing the look later (seed, density, shapes) is one file.
- Material 3 stays; the density and the "less chrome" defaults are overrides of its themes, not a custom design system.
- With a pointer, dense rows and 48 dp app bars give more content per screen. On phones the touch targets stay accessible (48 dp).

## Verification
- `packages/ui/test/theme_test.dart` (10 tests):
  - the palette and the meaning colours keep 3:1 on light and dark surfaces;
  - neutral, untinted bars and a muted primary;
  - each colour has its own dark tone;
  - density: compact with a pointer, 48 dp on phones;
  - Settings → System / Light / Dark changes the app at once.
- All 196 UI tests and 25 app tests pass after the migration, with the English text unchanged. Windows debug build OK.
- FF-ARCH-07: 126 packages (intl added). FF-ARCH-10 OK; a probe file with a raw string makes it fail.
- Mutations: 10/10 killed: platform density, app-bar height, two palette tones, scrolled-under elevation, the neutral variant, theme-mode mapping, a dark meaning colour, the settings refresh, and the FF-ARCH-10 rule (checked with the probe).
